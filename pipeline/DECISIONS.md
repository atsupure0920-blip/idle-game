# 決めたことの記録

設計書（開発パイプライン v3）から変えた点と、進めるうちに決めたことを、日付つきで残す。新しいものが下。

## 2026-10-10（S0）

### D-001 開発は、Claudeアプリが用意する作業環境の中で行う
- v3 では「Claude Code、Node.js、Git を PC に入れる」をユーザーの作業にしていた。
- 実際には、Claudeアプリが PC の上に用意する作業環境（Linux）に Node.js 22 と git があり、接続したフォルダを直接扱えた。
- そのため、Windows 側には何も入れない。ユーザーの導入作業はなくなった。

### D-002 依存とビルドは作業用コピーで行い、正本はこのフォルダに置く
- このフォルダは OneDrive の中（`OneDrive\Desktop\idle game`）にある。node_modules を置くと同期が重くなる。
- 接続フォルダの上では、削除に許可が要るなどの制限がある。
- そこで `scripts/vm/run.sh` が、毎回このフォルダから作業用コピーを作り、そこで検査とビルドを行う。
- ソースと履歴（.git）はこのフォルダにあるので、OneDrive がそのままバックアップになる。

### D-003 保護ファイルは、フックではなくスクリプトの照合で守る
- v3 では「フックで書き込みを止める」としていたが、この作業環境ではフックが働くことを確かめられない。
- 代わりに、承認時の指紋と照合する `scripts/check/protected.ts` を全検査と play の前に走らせる。
- 承認は `pipeline/APPROVALS.md` に日付と理由つきで残り、`status` に直近3件が表示される。
- 限界: これは「黙って変わったら気づける」仕組みで、書き換え自体を物理的に止めるものではない。

### D-004 コマンドは言葉で受ける
- `/status` などはアプリのコマンドとして登録されない。ユーザーは「status」「play」などの言葉を打つ。
- 手順は `pipeline/commands/` にあり、実体は `scripts/` のスクリプト。

### D-005 画面を自動で操作するテスト用のブラウザは、S3 で方法を決める
- 作業環境からは、テスト用ブラウザの配布元に到達できなかった。
- S3 で通し操作テストを作るときに、実行場所を決める（Claude 側の環境にはブラウザがある）。

### D-006 公開先は未決定
- 作業環境から到達できたのは GitHub だけで、Cloudflare と Netlify には到達できなかった。
- ユーザーと相談して決める。

### D-007 公開先は GitHub Pages（ユーザーの選択）
- 毎回の play で自動的に公開できることを優先した。無料枠の条件として、リポジトリは公開になる。
- 鍵（トークン）は `.secrets/github-token.txt` に置く。履歴の対象外（.gitignore）で、対象は1つのリポジトリ、権限は内容の読み書きだけ。
- `scripts/publish.ts` は、送る前に「鍵が履歴にも公開物にも入っていないこと」を確かめ、入っていれば中止する。
- 公開用の枝（gh-pages）に dist/ を送り、あわせて履歴（main）とビルド番号を送ってバックアップにする。
- 作業環境からは `*.github.io` に届かないので、公開URLそのものの確認は、Claude 側の別の経路とユーザーの iPhone で行う。

### D-008 S0 完了（2026-10-10）
- 機械の判定: 全検査、自己診断11件、履歴とビルド、公開用の置き場のビルド、いずれも合格。
- ユーザーの確認: iPhone で表示、ホーム画面への追加、開き直しても回数が残ること、ログの取り出し、すべて確認済み（build-2）。
  iPhone のログでは、エラー0件、ホーム画面から起動、保存の永続化が許可されていた。
- 独立の検証: GitHub から新しく取得し直し、依存を入れ直して、全検査・自己診断・出口の検査が通ることを確かめた。
  これは Claude 自身が行った機械的なやり直しで、別の検証役による確認ではない。
- GitHub Pages は、gh-pages の枝を送った時点で自動的に有効になった。
- GitHub のリポジトリの既定の枝は gh-pages になっている（先に送ったため）。動作には影響しない。
