# 画面の決まり

対象: `src/ui/`、`src/battle/`、`src/debug/`

- UI（一覧、ポップアップ、ボタン）は HTML/CSS で作る。戦闘の表示も、絵が入るまでは HTML/CSS（`src/ui/battleview.ts`）。
  PixiJS を入れる場合は、戦闘の表示の枠の中だけ（D-012）。
- 操作できる要素と、値を表示する要素には `data-testid` を付ける。自動の通し操作テストがこれを使う。
- 画面はルールを持たない。値の計算は core に任せ、画面は結果を表示するだけ。
- 実際の時刻と保存領域を扱うのは `src/ui/` だけ。core へは値として渡す。
- 保存は、状態が変わったときと、画面が隠れるとき（`visibilitychange`、`pagehide`）に行う。
- 読めないセーブは、上書きする前に別名で残す。新しい版のセーブは上書きしない。
- ファイルの参照は相対パスにする（公開先の階層が変わっても動くように）。
- iPhone の縦持ちを基準にする。押す場所は 44px 以上。ノッチとホームバーの余白（safe-area）を取る。
- 画面に必ずビルドの番号を出す（確認用ビルド）。どのビルドを遊んでいるかを取り違えないため。
- デバッグ機能は `__DEBUG__` が真のときだけ動かす。公開用ビルドには入れない。

## 画面の作り

- `src/ui/session.ts`（進行役）: ゲームの状態を持ち、時間を進め、保存し、プレイの記録を付ける。DOM に触れない。
  時計と保存領域は外から受け取る（`tests/flow.test.ts` が、にせの時計で通しの流れを確かめる）。
- `src/ui/views.ts`: 各画面の中身（HTML の文字列）を作る。DOM に触れない。押せる要素には `data-action` を付ける。
- `src/ui/battleview.ts`: core が計算済みの戦闘を、時間どおりに再生する。勝ち負けを決めない。
  戦闘をしていない間は、次の面の顔ぶれを並べる。相棒の行動（actor が -1）は、真ん中の札から出す。
- `src/ui/main.ts`: 上の3つをつなぐ。`data-action` をまとめて受け、0.2秒ごとに時間を進めて描き直す。
  端末の日付（日課の入れ替え）を core に渡すのも、ここ。
- 画面は、下のタブ6つ（旅、団員、編成、相棒、勧誘、ミッション）と、上の帯の「≡」（旅の記録と設定）。
- 勝てる見込みの数字は、どの画面にも出さない（契約書の決定19）。
- 団員の画面は「上に選んだ団員の札、下に一覧」（`ui.hero`）。札の中のレベルの指定と装備の選択だけがポップアップ（`ui.detail`）。
- 「上げられるだけ全部」のような、量を選べないまとめ操作は置かない（決定28）。
- 注意書きは画面に並べず、各画面の「？」（`helpHtml`）にまとめる。画面に出すのは、いまの状況だけ。
- 赤い印は、すぐにできて意味のあることがあるときだけ付ける（勧誘は10連を回せるとき）。まとめる操作には、何がどれだけ変わるかを出す。
- ポップアップの中の長い文は、ボタンに入れず、ボタンの下の小さい文字に出す（ボタンの文字は折り返さないので、切れる）。
  通し操作テストが、ポップアップの中身のはみ出しを検査する。
- 画面を描き直すのは、中身が変わったときだけ（押している途中のボタンを作り直さないため）。
- 時間とともに変わり続ける値（箱の中身）は、HTML に書き込まない。`data-live="名前"`（文字）か `data-live-width="名前"`（棒の幅）を
  付けた要素を置き、`journeyLive()` が返す値を main.ts があとから書き込む。
- ポップアップは、出てから0.4秒はボタンを受け付けない（連打していた指の押し間違いを防ぐ）。外の暗いところを押すと閉じる。
- 描き直しても、スクロールの位置を変えない。スクロールする箱には `data-scroll-key` を付ける（main.ts が位置を保つ）。

## 画面を変えたとき

1. `npm run e2e`（Claude 側の環境。ビルドして、本物のブラウザで通し操作テストを走らせる）。
2. `reports/e2e/*.png` を見て、見た目が崩れていないか確かめる。
3. `pipeline/reports/e2e-last.json`（結果の記録）を、ソースと一緒に記録（コミット）する。
4. ユーザーのPCへ送り、`play`。記録の指紋がソースと合わなければ、play は通らない。
