# core（ルール）の決まり

対象: `src/core/`、`src/sim/`

- 画面（DOM）、保存領域、Node.js の機能に触れない。
- 実際の時計に触れない。時刻は `nowMs` として引数で受け取る。`Date.now()`、`new Date()`、タイマーは使えない。
- `Math.random()` を使わない。乱数は `Rng`（`src/core/rng.ts`）を使い、内部状態を状態に保存する。
- 状態は書き換えず、新しい状態を返す。
- 模擬プレイ（`sim`）は、必ず core の関数を呼ぶ。ルールを二重に書かない。
- 数値は式に直接書かず、パラメータ（`params/`）から受け取る。
- 状態の形を変えたら `STATE_VERSION` を上げ、`MIGRATIONS` に変換を足し、旧版のセーブを読むテストを足す。
- 端末の時計の変更に備える。時刻が前回より過去なら、経過時間は0として扱う。放置報酬には上限を置く。

これらは `scripts/check/core-purity.ts` と `tsconfig.core.json` が機械的に検査する。

## 数値を変えたとき

- 数値（`params/`）や団員の定義を変えたら、`bash scripts/vm/run.sh acceptance` を走らせる。合否の数字に落ちたままにしない。
- 合否の数字（`spec/ACCEPTANCE.yaml`）のほうを、通すために変えない。変えるのはユーザーの実プレイと食い違ったときだけで、承認が要る。
- 模擬プレイの遊び方（`src/sim/policies.ts`）を、通すために都合よく変えない。変えるのは、実際の人の遊び方に近づけるときだけ。
- ルールの単体テスト（`tests/game.test.ts`）は、テスト専用の数値で書く。本番の数値を調整しても壊れないようにする。
